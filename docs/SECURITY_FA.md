# امنیت فراخوانی ابزار در برنامه‌های LLM

## ساختار درست، مجوز درست نیست

مدل ممکن است یک JSON کاملاً معتبر تولید کند، اما درخواست مربوط به منبعی باشد که کاربر اجازهٔ دسترسی به آن را ندارد. این نسخه بعد از JSON Schema یک سیاست جداگانه را بررسی می‌کند.


```bash
python -m tool_call_validator.security examples/valid_persian.json --schemas examples/tools.json --policy examples/security_policy.json
```

این دستور هیچ ابزاری اجرا نمی‌کند. کد خروج صفر یعنی بررسی‌ها اجازه داده‌اند، یک یعنی درخواست رد شده و دو یعنی مشکل تنظیمات یا ورودی.

## چه کنترل‌هایی اضافه شده‌اند؟

- ابزار ثبت‌شده در schema هم باید در policy مجوز داشته باشد؛ نبودن یعنی رد شدن.
- allowed_values مقادیر رشته‌ای مجاز را دقیق و حساس به بزرگی حروف تعیین می‌کند. مثلاً فقط site-001.
- max_values سقف عدد صحیح غیرمنفی را تعیین می‌کند؛ رشتهٔ عددی و boolean پذیرفته نمی‌شوند.
- فیلدی که در سیاست محدود شده باید وجود داشته باشد، حتی اگر schema آن را اختیاری بداند.
- شکل نامعتبر سیاست یا کلید اضافی به‌جای نادیده‌گرفتن خطا ایجاد می‌کند.

نمونهٔ سیاست جستجو فقط زبان فارسی و حداکثر سه نتیجه را می‌پذیرد. پیش‌بینی فقط برای site-001 و تا ۲۴ ساعت مجاز است. این‌ها مثال آموزشی‌اند، نه مجوز واقعی کاربران.

## مرز اعتماد

سیاست باید در سرور و بر اساس هویت احرازشدهٔ کاربر ساخته شود. آن را از prompt، پاسخ مدل، متن بازیابی‌شده یا آرگومان approved نخوان. دسترسی ابزار واقعی هم باید دوباره در سیستم مقصد بررسی شود. این کتابخانه هویت، نقش، تأیید انسانی یا نشست کاربر را پیاده نمی‌کند.

جریان پیشنهادی: احراز هویت → ساخت سیاست محدود برای همان درخواست → اعتبارسنجی schema → بررسی سیاست → اجرای همان درخواست با همان مجوز در ابزار مقصد. سیاست یا آرگومان‌ها نباید بین بررسی و اجرا عوض شوند.

## چه چیزی را حل نمی‌کند؟

این بررسی تشخیص عمومی prompt injection، فیلتر محتوای مضر، جلوگیری از SSRF یا sandbox نیست. فقط فیلدهای سطح اول را محدود می‌کند. رشتهٔ query می‌تواند همچنان متن نامطمئن باشد. هیچ جستجوی چند کلمه‌ای نمی‌تواند تضمین کند که تمام تزریق‌های دستور پیدا شده‌اند.

گزارش این مسیر امنیتی آرگومان‌ها و متن خطاهای schema را نشان نمی‌دهد؛ فقط کد دلیل برمی‌گرداند. گزارش‌های قدیمی validate-tool-call این رفتار را ندارند و ممکن است مقادیر ورودی را نمایش دهند.

## تمرین

۱. site-001 را به site-002 تغییر بده: JSON معتبر است، اما سیاست باید رد کند.
۲. ابزار را از policy حذف کن: ثبت بودن در schema نباید کافی باشد.
۳. hours را رشته بفرست یا سقف را بیشتر کن: رد شدن را بررسی کن.
۴. approved: true را به درخواست اضافه کن: مدل نباید خودش مجوز بسازد.

مبنای طراحی، اصل کمترین دسترسی و کنترل مجوز خارج از مدل است؛ [راهنمای OWASP دربارهٔ Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) و [راهنمای پیشگیری از Prompt Injection](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) را ببین. این پروژه گواهی امنیت یا پوشش کامل تهدیدها ارائه نمی‌کند.
